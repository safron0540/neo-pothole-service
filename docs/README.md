# Документы бэкенда

Порядок чтения для нового участника: `status.md` → `project-overview.md` → нужный раздел ниже. Правила Git и PR собраны в `dev-plan.md`, устройство кода — в `architecture.md` (раздел 7).

| Файл | Что внутри | Когда открывать |
| --- | --- | --- |
| [status.md](status.md) | Что уже слито, что в работе, следующий шаг, что блокирует | В начале каждой сессии |
| [project-overview.md](project-overview.md) | Зачем система, роли, жизнь заявки, сроки, ключевые понятия | Чтобы понять проект целиком |
| [architecture.md](architecture.md) | Требования → решения → стек → C4 → UML → бизнес-правила → API → безопасность → эксплуатация → тесты; трассировка REQ | Перед любой новой функцией |
| [db-schema.md](db-schema.md) | 17 таблиц с полями, связи, допустимые значения, вычисляемое, индексы, триггеры, начальные данные, миграции | При моделях, миграциях и запросах |
| [dev-plan.md](dev-plan.md) | Все PR по фазам 1–7 с коммитами и критериями готовности, правила Git, чек-лист PR | Когда начинаешь новый PR |
| [open-questions.md](open-questions.md) | 37 вопросов к команде с рекомендациями, несостыковки ЧТЗ и ТУТ | Когда задача упирается в решение [D] или вопрос |

Диаграммы: картинки в [img/](img/), исходники draw.io в [diagrams/](diagrams/) (`architecture.drawio` — 7 страниц C4 и UML, `er-model.drawio` — логическая и физическая ER-модели). Открываются на app.diagrams.net или в расширении Draw.io для VS Code.

Правило обновления: изменение БД идёт одним PR — миграция → `db-schema.md` → ER-диаграмма. Решение по вопросу из `open-questions.md` переносится в основной документ, а пометка [D] там снимается.
