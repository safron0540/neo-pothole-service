# Нагрузочный тест (фаза 6-3)

Проверяем ПР-1 (экраны ≤ 2 с), ПР-2 (95 % запросов API ≤ 1 с), ПР-6 (карта ≤ 4 с) при нагрузке ПР-9 (50 одновременных пользователей).

## Как запускать

- **JMeter** (для приёмки): [`tests/load/plan.jmx`](../tests/load/plan.jmx).

  ```bash
  jmeter -n -t tests/load/plan.jmx -Jhost=127.0.0.1 -Jport=8080 -Jlogin=dispatcher -Jpassword=… -l result.jtl -e -o report/
  ```

- **Без JMeter**: [`tests/load/load_check.py`](../tests/load/load_check.py), сценарий тот же.

  ```bash
  BASE_URL=http://127.0.0.1:8080/api/v1 LOGIN=dispatcher PASSWORD=… python tests/load/load_check.py
  ```

**Сценарий.** 50 диспетчеров одновременно, 60 с, пауза «человек смотрит на экран» 1 с. Каждый по кругу открывает:

- список заявок;
- карточку заявки;
- точки карты всего Томска;
- тепловую карту всего города (zoom 11) и центра (zoom 14);
- отчёт.

Каждому пользователю свой `X-Forwarded-For`: иначе nginx посчитал бы всех одним IP.

## Результат 27.10.2026

**Стенд.** Полный стек `docker compose` (nginx → backend, один процесс uvicorn → PostGIS) на машине разработчика (12 ядер).

**Данные.** Демо-база: 396 заявок и 16 331 кусок дорог Томска, включая дворы.

| Запрос                    | p50 до, с | p95 до, с | p50 после, с | p95 после, с |
|---------------------------|-----------|-----------|--------------|--------------|
| Список заявок (ПР-1)      | 0,96      | 2,61      | 0,30         | 0,70         |
| Карточка заявки           | 1,12      | 2,75      | 0,27         | 0,67         |
| Точки карты: город (ПР-6) | 1,27      | 2,92      | 0,40         | 0,84         |

Ошибок нет. ПР-1, ПР-2 и ПР-6 выполняются.

## Что нашёл тест и что исправлено

1. **JIT PostgreSQL.** Запрос тепловой карты выглядел для планировщика дорогим, и PostgreSQL компилировал его заново на каждом вызове: 0,2–0,5 с при самом запросе в 0,1–0,2 с. Под нагрузкой база была занята на 11 ядер из 12. Для соединений приложения JIT выключен (`app/db.py`).
2. **Соседние куски улицы для тепла.** Раньше их искали по расстоянию: около 300 кандидатов на каждую яму. Теперь ищут по названию, а расстояние проверяют только у них; тепло получается то же.
3. **Устаревший IP backend в nginx.** После перезапуска контейнера backend nginx отвечал 502, потому что помнил старый адрес. Теперь адрес берётся из DNS Docker заново (`resolve` в `infra/nginx/nginx.conf`).

**Узкое место сейчас.** Один процесс Python: под этой нагрузкой backend занимает около 100 % одного ядра. Если на стенде будет хуже, можно добавить процессы uvicorn (`--workers`). Тогда метрикам Prometheus понадобится режим multiprocess.
